# Verses / Think Different — Workflow Guide

**Source of truth:** `main` contains the website, backend, and Expo mobile app. Make and merge all normal development changes there. Release branches only select which version each hosting service deploys.

**Updated:** 22 October 2026

---

## Branches and releases

| Branch | Purpose | What a push deploys |
| --- | --- | --- |
| `main` | Canonical code for the entire monorepo | Nothing automatically by this branch policy |
| `deploy` | Website release branch | Netlify website |
| `deploy-backend` | Shared backend release branch | Both Render backend services |

The old `develop`, `develop-2`, and `backend` branches are historical. Do not use them for new work or deployment. Keep them until their history has been verified in `main`; deleting them is optional.

```text
feature branch → main ┬→ deploy          → Netlify website
                      ├→ deploy-backend  → both Render backends
                      └→ EAS build       → mobile app (manual)
```

The two Render services run the **same backend code** from `deploy-backend`. They can still use different environment variables and databases. Check the Render settings for each service before promoting a backend release. A push to `deploy-backend` can redeploy both services.

## Deployed services

| Service | URL | Release branch | Project root |
| --- | --- | --- | --- |
| Website (Netlify) | https://think-different-td.netlify.app | `deploy` | repository root |
| Website API (Render) | https://verses-backend.onrender.com | `deploy-backend` | `backend/` |
| Mobile API (Render) | https://verses-backend-dev2.onrender.com | `deploy-backend` | `backend/` |
| Mobile app (EAS) | APK/build link from EAS | build from `main` | `verses-mobile/` |

The branch names above are the **intended settings**. `backend/render.yaml` declares `deploy-backend` for the website API. For each existing Render service, also set its linked Git branch to `deploy-backend` in Render if it is still pointing at `deploy` or `develop-2`. Confirm the service's root directory is `backend/` and auto deploy is configured as desired. The mobile API is a separate Render service and is not declared in the current YAML file.

Netlify must remain linked to `deploy`. `netlify.toml` describes the build; the production branch is selected in Netlify project settings.

## Start work

Use PowerShell from `D:\Projects\Amani\verses`:

```powershell
git status --short --branch
git switch main
git pull --ff-only origin main
git switch -c feature/describe-change
```

Make changes to the website (`app/`, `components/`, `lib/`, `data/`), backend (`backend/`), or mobile app (`verses-mobile/`) on the feature branch. Merge the finished work into `main` using a pull request or a local merge. Keep uncommitted work safe before switching branches. Do not develop directly on either deployment branch.

### Run locally

```powershell
# Website, from repository root
npm.cmd install
npm.cmd run dev
# http://localhost:3000

# Backend, from backend/
cd backend
npm.cmd install
npm.cmd run dev
# http://localhost:5000

# Mobile, from verses-mobile/
cd ..\verses-mobile
npm.cmd install
npm.cmd start
```

The `.cmd` form avoids PowerShell script execution policy errors on some Windows machines.

### Check before merging to `main`

```powershell
# From repository root
npm.cmd run build

# From backend/ when backend code changed
node --check src/server.js
```

The backend currently has no automated test script. Check its health endpoint after a release. Use the mobile project's relevant local checks when mobile code changed. Check `git status` before committing so generated files and unrelated edits stay out of the commit.

## Release the website

After the desired changes are on `main`, promote that commit to `deploy`:

```powershell
git switch main
git pull --ff-only origin main
git switch deploy
git pull --ff-only origin deploy
git merge --ff-only main
git push origin deploy
git switch main
```

The push triggers Netlify. Render should no longer follow `deploy`. A website release branch receives the full repository snapshot, but only the website service builds from it. If `--ff-only` fails, stop and inspect the branch history; do not force push a deployment branch.

## Release the backend

After the desired changes are on `main`, promote that commit to `deploy-backend`:

```powershell
git switch main
git pull --ff-only origin main
git switch deploy-backend
git pull --ff-only origin deploy-backend
git merge --ff-only main
git push origin deploy-backend
git switch main
```

This push is intended to trigger **both** Render services. Check each service's Deploys page and `/api/health` afterward. With this shared branch, a backend change cannot be released to only one of the two services through Git branch promotion.

If a release needs both website and backend changes, promote the same `main` commit to both release branches. Release the backend first when the website depends on a new API response.

## Build the mobile app

```powershell
git switch main
git pull --ff-only origin main
cd verses-mobile
npx.cmd eas build --profile preview --platform android
```

Always run EAS from `verses-mobile/`. The mobile app currently calls `https://verses-backend-dev2.onrender.com/api` from `verses-mobile/lib/api.ts`; rebuilding is required after changing that URL. Mobile APK publication remains manual.

## Environment and data

The backend uses MongoDB and requires `MONGODB_URI` and `JWT_SECRET`. Keep credentials in Render environment variables or local `backend/.env`, never in Git. Typical settings include `NODE_ENV`, `PORT`, `JWT_EXPIRES_IN`, `CORS_ORIGIN`, and rate limit values; see `backend/src/config/env.js` and `backend/render.yaml` for the code's defaults and declared production values.

Use **separate MongoDB credentials or databases** if the mobile service is meant to be a staging environment. Sharing a Git branch does not isolate data. Set `CORS_ORIGIN` for the website API to the Netlify origin; verify the mobile service's CORS value in its own Render settings.

### Troubleshooting

- **Backend slow after inactivity:** Check Render Deploys and Logs; free instances may need time to start.
- **Website API/CORS error:** Verify the website API URL and `CORS_ORIGIN` on the production Render service.
- **Mobile data not loading:** Check the mobile API URL, its Render deployment, and its MongoDB connection.
- **Wrong code deployed:** Check the linked branch in Netlify or Render settings and compare its commit with the intended `main` release commit.
- **Mobile build failure:** Run EAS inside `verses-mobile/`; verify `app.json` plugins and package dependencies.

For a branch check at any time, run `git status --short --branch` and `git branch -avv` from the repository root.
